# BUG-001 — Selector keeps using csg after tpr activation

## Summary

The selector's Apply path is:

```ts
// lib/apply.ts
const args = ["dotfiles-runtime", "wallpaper", "set", imagePath];
return execAsync(args);
```

`execAsync` inherits the selector process environment. The runtime's producer is
selected from `RUNTIME__PALETTE__PRODUCER` at the composition root. The
provisioned session has tpr in:

- `~/.config/environment.d/10-dotfiles-runtime.conf`
- the `dotfiles-runtime-daemon.service` unit

but a long-running AGS selector that predates the environment update keeps the
old value. The selector does not read the producer from the daemon, a stable
runtime config, or the current environment.d; it silently calls CSG. This makes
the selector's behavior disagree with the runtime and with the tpr cache keys.

## Evidence (live host, 2026-10-29)

```text
$ cat ~/.config/environment.d/10-dotfiles-runtime.conf
RUNTIME__PALETTE__PRODUCER=tpr

$ systemctl --user show dotfiles-runtime-daemon.service -p Environment
Environment=RUNTIME__PALETTE__PRODUCER=tpr

$ ps -o pid,lstart,cmd -p 716589
716589  Wed Oct 29 17:33:40 2026  ags run -d /home/inumaki/.config/ags-wallpaper-selector ...

$ tr '\0' '\n' < /proc/716589/environ | grep RUNTIME__PALETTE
RUNTIME__PALETTE__PRODUCER=csg
```

The selector started after bootstrap, but environment.d applies to new login
sessions; the process was started with the old session environment. A wallpaper
apply from this selector therefore runs CSG. `failures.jsonl` records the
failures as `tool: csg` (for example, `white_tailed_eagle.png` and `shani.png`);
a direct `RUNTIME__PALETTE__PRODUCER=tpr ... dotfiles-runtime wallpaper set`
succeeds with the tpr cache entry.

## Why it matters

- The user cannot rely on the tpr cutover while using the selector.
- CSG and tpr produce different cache keys and palettes; the selector can
  generate two different themes for the same wallpaper depending on who
  started it.
- The failures the user sees are CSG failures, not tpr/native failures, which
  makes the tpr cutover look broken.

## Fix direction (triage)

1. **Stable producer source.** The selector should not trust its inherited
   `RUNTIME__PALETTE__PRODUCER`. Resolve the producer from the same source the
   runtime daemon uses (environment.d/daemon config, or a runtime command that
   reports the active producer), and fail loud if it cannot.
2. **Restart/refresh contract.** If the intended activation mechanism is
   environment.d, provisioning must restart the AGS apps (or the session) after
   a producer change; otherwise the old process env remains indefinitely.
3. **Visible mismatch.** Add a startup/check that warns when the selector's
   producer differs from the daemon's, and a test that a selector launched
   before environment.d is updated does not silently use the old producer.
4. **Workaround for the current host:** log out/in (or restart the AGS selector
   after environment.d is active) so it inherits tpr. The code fix must make
   this unnecessary.

## Done-when

- [ ] A selector apply after tpr activation uses `tpr` and the tpr cache key,
  even if the selector process was started before environment.d changed.
- [ ] A producer mismatch is surfaced, not silently ignored.
- [ ] The selector's apply tests cover an inherited stale producer.
- [ ] Any restart/refresh behavior is coordinated with `dotfiles-provision`
  BUG-007 and the runtime producer seam.
